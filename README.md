# BARUCH

**B**idirectional **A**ST **R**eader and **U**nparser for **C**ommonMark, **H**ookable: a Markdown parser and emitter
in pure Fortran.

[![CI](https://github.com/szaghi/BARUCH/actions/workflows/ci.yml/badge.svg)](https://github.com/szaghi/BARUCH/actions/workflows/ci.yml)
[![Matrix](https://github.com/szaghi/BARUCH/actions/workflows/matrix.yml/badge.svg)](https://github.com/szaghi/BARUCH/actions/workflows/matrix.yml)

BARUCH reads Markdown into a document tree and writes a tree back to Markdown:

- **Reader**: CommonMark 0.31.2, block structure first and inlines second, checked against the spec's examples; the
  tree is read through its accessors or as a walk of events (enter and leave a block or a span, text).
- **HTML**: the tree as cmark writes it, an HTML fragment to embed in a page (no wrapper, no style sheet, no script)
  or a standalone page.
- **Writer**: the tree back to CommonMark. The round trip is semantic: re-reading what BARUCH writes gives the same
  tree, though not necessarily the same bytes.
- **Streaming writer**: Markdown emitted block by block, for reports produced while a program runs, with no tree.
- **Hookable**: GitHub's extensions (tables, strikethrough, task lists, autolinks, alerts, footnotes) and VitePress
  syntax (custom containers, math, front matter, anchors, attributes, snippet imports) as opt-in extensions, all
  through one public interface; the CommonMark core does not change when they are off.

Text is handled with [StringiFor](https://github.com/szaghi/StringiFor) and kinds come from
[PENF](https://github.com/szaghi/PENF), both fetched by `fobis fetch`.

Work in progress: the document tree, its input, the extension interface, the CommonMark block parser (the block
structure of CommonMark 0.31.2, source style recorded), the inline parser (escapes, character references, code
spans, autolinks, raw HTML, line breaks, emphasis, links, images, references), the HTML renderer and the event walk
are written, with the conformance harness that runs the 652 CommonMark 0.31.2 examples
(`bash scripts/spec.sh commonmark`: 652/652); the writers are not yet. The plan is [#1](https://github.com/szaghi/BARUCH/issues/1).

## Quick start

A Markdown text read into a document and written back as HTML (an HTML fragment, ready to embed in a page):

<!-- generated: docs/examples/snippets/hello.f90 fortran -->
```fortran
program hello
!< Quick start: a Markdown text read into a document and written back as HTML.
use baruch
implicit none
type(markdown_document)   :: doc     ! the document: its source and its tree
type(markdown_options)    :: options ! what a parse does: here CommonMark alone
character(:), allocatable :: html    ! the HTML

call doc%load('# Hello, BARUCH'//new_line('a')//new_line('a')// &
              'A Markdown reader in pure Fortran:'//new_line('a')//new_line('a')// &
              '- blocks parsed'//new_line('a')//'- HTML written'//new_line('a'))
call options%parse(doc)
call options%render_html(doc, html)
write(*, '(A)', advance='no') html
endprogram hello
```

Build the library and compile the program against it:

```bash
fobis fetch && fobis build --mode static-gnu
gfortran -Ilib/gnu/static/mod hello.f90 lib/gnu/static/libbaruch.a -o hello
```

The program and its output are generated by `scripts/docs_examples.sh` from `docs/examples/src/hello.f90`. The tests:

```bash
fobis fetch && fobis build --mode tests-gnu && bash scripts/run_tests.sh
```
